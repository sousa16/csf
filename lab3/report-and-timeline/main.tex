\subsection{Recovery and reconstruction of the hidden files}
\label{sec:q1}
% -----------------------------------------------------------------------------

\textbf{Question 1.} \textit{Which of the eight hidden files can be recovered or
reconstructed from the provided artifacts, and how?}

\textbf{Method.} Every object was exported from each decrypted capture and
hash-matched against the Lab~2 Table~2 digests:

{\footnotesize
\begin{verbatim}
for t in t1 t2 t3; do for p in http imf ftp-data tftp; do mkdir -p work/$t/$p
  tshark -r artifacts/$t.pcapng -o tls.keylog_file:artifacts/$t-tls.keys \
     -d tcp.port==8080,tls -d tcp.port==8443,tls -q --export-objects $p,work/$t/$p
done; done
find work -type f -exec sha256sum {} + > all.txt        # then grep each Table-2 hash
\end{verbatim}}

The matches:

\textbf{Observations.} The three byte-exact matches in t1 (\texttt{f2.json},

of AMA's intranet document repository; \texttt{f2.json} is simultaneously the
\emph{live} tool configuration served by the AMÉLIA node, so the Lab~2 ``system
tools configuration file'' is AMÉLIA's production schema. \texttt{f1.png} is
fetched from its public Reddit source. \texttt{f5.py} is byte-identical to the
Lab~2 training script and travels inside the \texttt{rag-isotropy-release.zip}
that Tiago's host uploads to ChatGPT (§\ref{sec:q4}). \texttt{f8.webp} is the
Telegram screenshot moved over the AMA-Workstation-Agent (§\ref{sec:q3}).

edition of the same technical-assurance report (two sentences removed), so its
content is recovered but not its exact bytes. \texttt{f7} is recovered as the
\emph{deployed} patched source \texttt{query\_translator.py}, which equals the
``\texttt{+}'' side of \texttt{f7.diff}; the unified diff itself is not transmitted
and the git fetch was incremental (the pre-patch blob is absent), so the diff
cannot be regenerated byte-for-byte. \texttt{f6.json} never appears in cleartext;
it exists only inside the GPG archive exfiltrated from Rui Fisco's workstation.

export GNUPGHOME=$(mktemp -d)
gpg --batch --import ftp_rfisco-maintenance.gpg
gpg --batch --pinentry-mode loopback --decrypt ftp_storage_maintenance.tar.gz.gpg \

\end{verbatim}}

(The secret key is \emph{not} submitted; f6 is credential material and is held

\textbf{Question 6.} \textit{What conclusions does the combined evidence support
about the allegations; the responsibility of the individuals, for and against;

  \texttt{armando.sacos} to let the award pass and to keep inquisitive juniors
  ``formatting Excel tables''.
\end{itemize}

\textbf{For and against individual attribution (hypotheses).} The evidence binds
actions to \emph{hosts/accounts}, not provably to the fingers on the keyboard, so
the following are forensic hypotheses, not established facts. A \textbf{framing
hypothesis} is the best fit for the combined evidence: the incriminating
\texttt{f8.webp} was observed being \emph{written onto} Tiago's workstation from
Armando's host (A315, E11), and Tiago's own voice note (A332, E5) states that
files were planted on his drive to make it look like he did it and that he was
moving them off himself. Under this reading Tiago is an insider who \emph{found}
the manipulation and was framed, while the technical execution sits with Data
Engineering (the \texttt{rfisco} commit, A313) and Cloud Operations (Vítor's
deployment, A330), under the Technical Director (Armando) and external political
pressure (A331). The opposing reading cannot be excluded: Tiago's host does
conduct the intrusions (TFTP, FTP brute-force, config/key theft, A310/A314), the
git author line is only an identity claim, and the voice note is a self-report
that could be self-serving; a clean re-transcription of the Armando$\rightarrow$Rui
voice note (A334) may bear on this. The Ricardo~Vale / Inês~Paralelo thread

data, and Inês herself states ``we never touched AMELIA''.
